## 1. 사업모델·기능 우선순위 검토

### 1-1. 기획과 다르게 판단한 부분 (승인 필요)

| # | 기획 | 판단 | 근거 |
|---|---|---|---|
| A | 초기 요금: 프리미엄 7일 5만 / VIP 30일 15만 | **요금 역전.** VIP가 하루 5,000원으로 프리미엄(하루 약 7,143원)보다 싸다. 상위 상품이 더 싸면 프리미엄이 팔리지 않는다 | 기간을 맞춘 요금표가 필요. 예: 프리미엄 7일 5만·30일 15만 / VIP 7일 9만·30일 25만 (가설). 관리자 화면에서 가격·기간을 바로 바꿀 수 있게 구현해 둠 |
| B | 추천 스택: Supabase Auth + Supabase Realtime | **DB는 PostgreSQL(Supabase 사용 가능) 그대로. 인증·실시간은 서버가 직접 처리**하도록 바꿈 | ① Supabase Realtime의 DB 변경 구독은 행 전체(보낸 사람 user_id 포함)를 브라우저에 보낸다. 익명성 요구(내부 ID 비노출)와 충돌한다. 서버가 보낸 사람 ID를 빼고, 차단 필터를 적용한 뒤 내려보낸다. ② 이 개발 환경에는 Supabase 프로젝트가 없어 테스트할 수 없다. 로컬 PostgreSQL로 모든 기능을 실제 검증했다 |
| C | 공고 등록: 구인자 | **기업 인증을 마친 구인자만** 등록. 일반 공고는 무료 유지 | 직업정보제공사업자는 구인자의 기업 정보를 확인해야 한다(2023.3.28 시행 시행령). 허위 공고 방지에도 직결된다 |
| D | 다중 계정·사칭 방지 | 실효 수단은 **휴대폰 본인인증**. 유료이고 계약이 필요하다 | MVP에는 닉네임 유일성, 운영자 사칭어 금지, 30일 변경 제한, 변경 이력, 신규 계정 링크 금지, 도배 제한까지만 넣었다. 본인인증 연동은 출시 전 필수로 권장 |

### 1-2. 추가로 반영한 리스크 대응
- **익명 게시판·현장 채팅의 명예훼손 위험**: 특정 현장이나 대행사를 비방하는 글이 핵심 리스크다. 신고 사유에 '권리침해'를 따로 두고, 운영자 숨김(임시조치)과 처리 기록이 남도록 했다. 정보통신망법 제44조의2 절차는 출시 전에 운영정책으로 확정해야 한다.
- **채팅 분산 방지**: 처음에는 전국 자유채팅과 4개 지역(서울·경기·인천·부산)만 연다. 나머지 지역은 관리자가 연다. 현장 채팅은 누군가 입장할 때 만든다.
- **알선 오인 방지**: 연락처는 회원이 직접 '연락처 보기'를 눌러야 받는다. 이력서 전달이나 지원 대행은 없다. 사이트 하단에 '채용을 알선하지 않음'을 명시했다.

## 2. 메뉴·화면 구성 (확정안)

하단 탭(모바일)과 상단 메뉴(PC)는 **홈 · 구인구직 · 익명 라운지 · 분양현장 · 마이페이지** 5개로 같다. 채팅방 화면에서는 입력창 공간을 위해 하단 탭을 숨긴다.

| 경로 | 화면 | 핵심 요소 | 상태 |

| `/` | 홈 | 검색과 빠른 필터, 메인 배너(광고), 프리미엄 공고(광고), 최신 공고, 전국 채팅 입장 카드, 인기 채팅방, 인기글, 신규 현장, 공지 | ✅ |

| `/jobs/[id]` | 공고 상세 | 모집 조건표, 복리후생, 상세 내용, 현장 연결, 관심 저장, 연락처 보기(문의 집계), 허위 공고 신고, 작성 기업용 수정·마감 | ✅ |

### 주요 사용자 흐름
1. **구직자**: 홈 검색 또는 빠른 필터 → 공고 목록 → 상세 → (로그인) 연락처 보기 → 전화. 마음에 드는 공고는 관심 저장.
2. **구인자**: 가입 → 구인자 관리에서 기업 인증 신청 → 운영자 승인 → 공고 등록(심사 대기) → 운영자 승인·게시 → 광고 신청 → 결제 승인 → 즉시 상단 노출 → 기간이 끝나면 자동 해제.
3. **커뮤니티**: 라운지 → 전국 자유채팅 → 메시지 길게 누름(탭) → 1:1 대화, 신고, 차단.
4. **운영자**: 대시보드 대기 건수 → 기업 인증·공고 심사·신고 처리. 모든 조치는 감사 로그에 남는다.

## 3. 디자인 시스템

- **분양톡 고유 요소** (흔한 기본 템플릿 인상을 벗기 위해 추가)
  - **조건 바**: 모든 공고 카드와 상세 상단에 RT · 일비 · 정산 · 마감 4칸을 숫자 위주로 고정 배치했다. 칸 너비는 값 길이에 따라 가중치를 두어, 375px 화면에서도 값이 잘리지 않는다(E2E로 검사).
  - **익명 아바타**: 닉네임의 동물을 고정 이모지와 배경색으로 보여 준다. 계정 정보 없이 닉네임만으로 계산한다.
  - **직급 배지**(선택, 자기 신고): 기본값은 표시 안 함. 켠 회원만 닉네임 옆에 상담사·팀장·본부장·신입이 붙는다. 운영자가 확인한 경력이 아니라는 점을 익명성 안내에 적었다.
  - **채팅 레이아웃**: 아바타, 닉네임·배지·시간 머리글, 3분 안에 이어 보낸 메시지 묶음. 내 메시지는 네이비 말풍선과 아래쪽 시간으로 표시한다(카카오톡식 배치와 구분).
  - **브랜드**: 지붕 모양 말풍선 마크(모델하우스 + 대화, 창 3개 = 입력 중 점), 워드마크 '분양**톡**', 아파트 스카이라인 모티프(히어로와 채팅 카드에만 절제해서 사용), 파비콘.
- **색**: 흰색 바탕에 기본 팔레트 값이 아닌 전용 네이비(`navy-900 #0a1b44`)와 코발트(`brand-600 #2b4fe0`) 포인트. **광고는 노란 계열(`ad-*`)과 '광고' 라벨만 쓴다.** 일반 콘텐츠의 블루와 섞이지 않게 했다.
- **다크 모드 대비**: 바탕·표면·글자·선 색을 의미 토큰(CSS 변수)으로 분리했다. `data-theme="dark"`에서 값만 바꾸면 되고, 토글 UI는 다음 버전이다.
- **글꼴**: Pretendard(패키지 내장, 동적 서브셋). 줄바꿈은 `word-break: keep-all`로 단어 단위.
- **컴포넌트**: `card`, `btn-primary/navy/ghost`, `input`, `chip`, `tag`, 공고 카드, 광고 라벨, 통계 카드, 신고 시트(모바일은 하단 시트).
- **반응형**: 모바일 우선. 1024px 이상에서 상단 메뉴, 2열 본문, 우측 사이드바로 바뀐다. 모바일 가로 넘침은 6개 화면에서 0px로 확인했다.

### 익명성 설계
- 다른 회원에게 내려가는 메시지 형태는 `{id, nickname, body, createdAt, mine, deleted}`뿐이다. user_id와 이메일은 API 응답에도, 화면 HTML(RSC 페이로드 포함)에도 없다. 자동 테스트로 확인한다.
- 신고·차단·1:1 대화는 메시지·글 ID만 받고, 작성자는 서버가 찾는다.
- 운영자 화면은 이메일 일부를 가린다. 전체 이메일은 최고 관리자만 본다. 채팅 금지 같은 제재도 메시지 ID로 실행한다.

### 접근 권한
- 브라우저는 DB에 직접 접근하지 않는다. 모든 쓰기는 API를 거치고, 변경 요청은 같은 출처(Origin)만 허용한다.
- Supabase를 DB로 쓸 경우 public 스키마를 API에 노출하지 않는다(RLS를 켜고 정책을 두지 않거나 anon·authenticated 권한 회수). 앱 전용 DB 역할에는 DDL 권한을 주지 않는다.
- 관리자 작업은 `operator`(심사·신고·회원 제재)와 `super_admin`(상품 가격, 환불, 매출, 권한 부여)으로 나뉜다.

## 5. 기술 아키텍처와 개발 계획

```
브라우저 ──HTTPS──▶ Next.js 15 (App Router, Node 서버 상시 실행)
   │  └ SSE(EventSource) 채팅 스트림        ├─ 화면: 서버 컴포넌트가 DB 직접 조회
   │                                       ├─ API: /api/* (검증, 권한, Origin 확인)
   │                                       └─ 실시간: Postgres LISTEN/NOTIFY → 인스턴스별 분배
   ▼
PostgreSQL 16 (Supabase 또는 관리형 PG) ── 결제대행사(토스페이먼츠/포트원) · 스토리지(S3/Supabase Storage)
```

- 인스턴스를 늘려도 NOTIFY가 모든 인스턴스에 전달되므로 채팅이 그대로 동작한다. 접속 인원은 DB 하트비트로 센다.
- **배포 제약**: SSE 장기 연결 때문에 Vercel 같은 서버리스보다 **상시 실행 Node 서버**(AWS Lightsail/ECS, Fly.io, Railway, NCP 등)가 맞다. `output: standalone`으로 빌드된다.

| 단계 | 내용 | 상태 |
|---|---|---|
| M1 MVP | 1~4장 전부, 시연 데이터, API 테스트, 실시간 채팅 E2E | ✅ 이번 작업 |
| M2 출시 준비 | 실결제 연동(위젯 + 서버 승인은 구조 완성), 휴대폰 본인인증, 파일 업로드(현장 사진·인증 서류·배너 이미지), 비밀번호 재설정·이메일 인증, 알림 발송, 국세청 사업자 상태조회 API, 약관·개인정보처리방침, CSP 헤더, 오류 모니터링(Sentry 등), 백업(PITR), 배포 | ⬜ |
| M3 성장 | 카카오 간편 로그인, 지도 내장, 맞춤 공고 알림, 검색 고도화(형태소), 협력업체 광고, 다크 모드 토글, 레이트리밋 Redis 이전 | ⬜ |

### 출시 전 확인 사항 (외부·법률)
- 직업정보제공사업 신고. 신고번호를 하단에 표시해야 한다(자리 마련됨).
- 사업자등록. 통신판매업 신고 필요 여부를 확인한다. 결제대행사 가맹 조건이다.
- 개인정보처리방침과 처리 위탁(호스팅, 결제, 본인인증) 고지.
- 익명 게시물 권리침해 신고 처리 절차(임시조치) 운영정책.
