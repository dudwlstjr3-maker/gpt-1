# 검증 하네스

이 앱은 단일 HTML이라 테스트 러너가 따로 없다. 수정 후에는 **반드시 두 층 다** 돌린다.

```
node tools/check-logic.js          # 1층 — 로직   (456건)
node tools/check-ui.mjs            # 2층 — 화면   (150회)
node tools/check-flows.mjs         # 3층 — 조작   (119건)
node tools/check-ui.mjs --shots    # 화면 + 스크린샷(tools/_shots/)
```

세 명령 모두 문제가 있으면 종료 코드 1로 끝난다.

## 1층 — 로직 (`check-logic.js`)

`index.html` 안의 인라인 `<script>` 를 뽑아 Node `vm` 에서 실행하고 함수를 직접 부른다.
브라우저가 필요 없어 1초 안에 끝난다.

- `dom-stub.js` — 최상위 초기화 코드가 죽지 않을 만큼의 DOM·localStorage 스텁.
  렌더링을 흉내내려는 게 아니라 순수 계산 함수를 꺼내오는 게 목적이다. `Math.random` 은 시드 고정.
- `load-app.js` — 스크립트 추출 + vm 실행. 최상위 `const` 는 sandbox 전역으로 안 올라오므로
  선언 이름을 긁어 직접 `eval` 로 내보내는 에필로그를 붙인다. 결과는 `.app` 에 담긴다.

최상위 `const` 는 sandbox 전역으로 안 올라오므로 선언 이름을 긁어 **살아 있는 접근자**로 내보낸다
(값을 복사하면 `TD = tdNew()` 같은 재할당을 검증 쪽에서 볼 수 없다). 결과는 `.app` 에 담긴다.

검증 항목: 포커 수식 4개(참조 구현 대조 + 소스 문자열 대조), 핸드 평가기, 승률,
`analyze` 통합, **액션 순서 엔진**(차례·블라인드·BB 옵션·3벳·체크레이즈·올인·헤즈업),
**시퀀스 → 분석 어댑터**(실제 팟에서 나온 필요 승률·MDF·EV),
**포지션별 레인지 표**(표에 보이는 레인지 = 엔진이 쓰는 레인지),
**권장 스타일**(내 폭만 움직이고 상대 읽기는 그대로), **상금 사다리**(엔트리+리바이 개수당 정액),
토너먼트 프리셋·레벨·상금 배분, 대회 프로필·주간 일정, 성향 진단 60문항·7축,
드릴 260핸드, 저장소와 **백업 커버리지**(소스의 `DB.set(...)` 키를 긁어 백업이 전부 담는지 대조 —
v3.1 까지 `quizans`·`drillaxis` 가 빠져 있었다).

## 2층 — 화면 (`check-ui.mjs`)

폴더를 포트 8777 정적 서버로 띄우고 실제 Chromium 으로 7탭 × 3폭(1440·1024·390)을 돈다.

- 노출 텍스트의 `undefined` / `NaN` / `null` / `[object Object]`
- 콘솔 오류·경고, 페이지 예외
- 가로 넘침 (문서 전체 + 개별 요소. 스스로 `overflow-x` 를 갖는 컨테이너는 제외)
- **자기 상자보다 내용이 넓은 요소** — 화면 밖으로 안 나가도 그 자리에서 잘린다.
  가운데 정렬이면 좌우로 넘쳐 뷰포트 기준 검사에 안 걸리는데, `BREAK TIME` 이 그 경우였다.
- 대비비 (WCAG AA — 본문 4.5:1, 큰 글씨 3:1). 앱은 밝게·어둡게 양쪽,
  전광판은 테마 6종 × (진행 중 · 휴식 중)을 따로 돈다.

`color-mix()` 는 Chromium 이 `color(srgb 0.93 0.95 0.97 / 0.88)` 로 돌려주므로 0~1 스케일로 읽고,
반투명 배경은 뒤 배경 위에 합성해 실제 색을 구한다. 테마를 바꾼 뒤에는 CSS 트랜지션이
끝날 때까지 기다렸다가 색을 읽는다(중간값을 읽으면 엉뚱한 대비가 나온다).

## 3층 — 조작 (`check-flows.mjs`)

실제로 눌러 본다. 로직 검증은 함수를, 화면 검증은 정지 화면을 본다. 이건 그 사이 — DOM 배선이
실제로 이어져 있는지. **핸드 분석에서 액션을 순서대로 클릭해 쌓는 검사**(차례가 도는지, 폴드하면
넘어가는지, 레이즈 후 콜할 금액, 되돌리기, 플랍이 열리는 시점, 상대 벳을 맞으면 필요 승률이
나오는지, 헤즈업 첫 차례), 대회 프로필 저장→주간표 반영→열기→새로고침 후 유지→삭제,
전광판 테마 전환, 광고 슬라이드 추가·순서·삭제, 성향 진단, 드릴, 테마 유지, 저장 키.

`renderTDClock` 이 화면 전체를 `[data-act]` 로 훑어 다른 카드의 버튼 핸들러를 덮어쓰던 버그를
잡은 게 이 층이다 — 로직·화면 검증으로는 안 잡힌다.

컨테이너에 미리 깔린 `/opt/pw-browsers/chromium` 을 쓴다. `npx playwright install` 은 하지 않는다.
